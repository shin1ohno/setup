# structures.md — 文章構造の AI 臭パターン

文章の「形」に出る AI 臭。`phrases.md`（語彙）と直交する。AI 臭の正体は書き手の不在であり、記号や偏愛語は症状にすぎない。根本は主体（パターン 1）と文書の立場（パターン 11）にある。

1〜3 は Zenn 記事 algoartis/0b1c731881b25c（yomiyasu リポの `articles/yomiyasu-ai-writing-lint.md` と同文）が挙げる 3 つの言語学的病理を、記事の名前のまま節にしたもの。4 以降は従来の構造パターン。各パターンは AI版/人間版の対照、「問題（根本原因）」、判定（正規表現か `slop_scan.py` のルール id）を持つ。1〜3 には「足さない」制約も付ける。

共通の前提: 直すときに、原文と前後の文にない動作主・目的語・数値・原因・条件・例を足さない。足りないときは本文で補わず、「書き手に確かめたい点」に回す。

## 1. 病理① 非生物主語 ＋ 身体性比喩動詞（英語の直訳病）— 最優先

モノや概念を主語に置き、人の体や意志の動詞（語る・促す・倒す・効く・壊れる）で片付ける構文。英語の慣用句（silently break / works for / land on the safe side）の直訳が多い。誰が何をした結果なのかが文から消える。語彙の一覧は `phrases.md` 2（英語直訳）と 9（比喩動詞）。

| AI版 | 人間版 | 補足 |
|---|---|---|
| このログが障害の原因を語っている | このログに障害の原因が出ている | 所在・状態として書く |
| データが示している | データを見るとこうなっていた | |
| 課題が浮き彫りになる | 課題がはっきり分かった | 「やってみて」等の行為は原文になければ足さない |
| 文化が醸成される | 経営陣がこの文化を作った | 前後の文に経営陣が出ている場合だけ。なければ「この文化ができてきた」 |
| キャッシュがレイテンシに効く | キャッシュを入れるとレイテンシの改善に役立つ | 「下がる」「半減する」と狭めない |
| 設定変更が本番を静かに壊した | 設定を変えたあと、気づかないうちに本番が動かなくなった | 「静かに」は気づけない幅のまま。「エラーを出さずに」は原文で分かる場合だけ |
| 例外時は安全側に倒す | 例外が起きたら安全を優先して処理する | |

直す対象は擬人化（道具・概念に意志や感情を持たせる表現）だけ。道具の働きを客観的に書いた文（「このツールはログを集める」）はそのまま残す。比喩の語は言い換えてよいが、その語が運んでいた含み（「地味に」の目立たないが確かな感じ、「〜てしまった」の後悔）は別のふだんの言葉で残す。定着した慣用句（骨が折れる・手を焼く）と、物理的な物や身体の文字どおりの「壊れる」は直さない（`phrases.md` 9 の例外）。

問題: 行為者と因果が文から抜け、責任と具体が失われる。読み手は「現場で何が起きて、誰が対処するのか」を行間から補うことになる。
判定: `slop_scan.py` の `metaphor_verb`・`slop_vocabulary`・`inanimate_agency`（pathology "1"）。手で探すなら `(が|は)(語る|語って|示して|浮き彫り|醸成|促す|願う|教えてくれる)` と `phrases.md` 9 の語。
足さない: 直すときに元にない条件（「〜を使えば」）・可能（「〜できる」）・動作主を足さない。動作主を戻すのは、前後の文にその主体が書いてある場合だけ。強調語（「確かに」「大きく」）も足さない。

## 2. 病理② SVOCM 統語の消失と過剰な名詞化（日本語の過圧縮）

述語を動詞として展開せず、サ変名詞や漢語名詞を「の」で数珠つなぎにし、体言止めで締める圧縮。主語（S）・目的語（O）・動作（V）・条件（M）が消え、名詞だけが詰め込まれる。専門語が並んで賢そうに見えるが、手順としては何も伝わらない。

| AI版 | 人間版 |
|---|---|
| 保守性担保機能の形骸化の防止。 | コードの保守性を保つ仕組みが形骸化しないように、定期的なレビューを実施します。 |
| 監視基盤の閾値設定の見直し。アラート疲れの解消。 | 監視の閾値を見直して、アラート疲れを減らす。 |

1 行目は記事の例文。人間版の「定期的なレビューを実施します」は記事側の書き手が持っている文脈で、校正時に原文と前後になければ足さない。そのときは「形骸化しないようにする」まで開き、手段は「書き手に確かめたい点」に回す。

開き方: 名詞の連鎖を「誰が・何を・どうする」の動詞文にする。「これ」「両者」は、指す先が前後から分かるときだけ名詞に戻す。漢語が続いて硬いところは動詞や和語に開く。

問題: 動作主・対象・動作の関係が読み取れず、文が命令なのか目標なのか状態なのかも決まらない。
判定: `slop_scan.py` の `nominal_chain`（2 字以上の漢語・カタカナ名詞が「の」で 3 つ以上つながる）と `taigen_run`（表・箇条書き・見出し・コード以外の地の文で、体言止めの文が 3 文以上続く）。どちらも pathology "2"。手で探すなら `[一-龯ァ-ヶー]{2,}の[一-龯ァ-ヶー]{2,}の[一-龯ァ-ヶー]{2,}`。
足さない: 補ってよい動作主・目的語は前後の文に明示されているものだけ。開いた結果、動作主が文脈から決まらないときは主語なしの動詞文で止める（日本語は主語を省いてよい。7 と両立する）。

## 3. 病理③ 形式インフレと架空の敵を立てる否定対比

二つの症状が同じ根を持つ。一つは「〜ではなく〜だ」「単なる〜ではない」で、読者が抱いていない誤解を先回りで作って否定してから本題に入る対比。肯定文だけで伝わる内容に、演出の否定が積み重なる。もう一つは太字・箇条書き・ラベル・絵文字の乱発で、スキャンしやすい体裁を装うだけで中身は増えない。

| AI版 | 人間版 |
|---|---|
| これは単なるリファクタリングではない。設計の転換だ。 | このリファクタリングで設計が変わった |
| 単なるツールではない。作業の組み立て方が変わった。パラダイムシフトだ。 | このツールで作業の組み立て方が変わった |
| - **速度:** 処理速度が 3 倍に向上 | - 処理速度が 3 倍に向上 |
| - **コスト:** 月額が半減 | - 月額が半減 |
| **ポイント**は、**キャッシュ**を**先に**温めることです | キャッシュを先に温めておくのが大事です |

残す否定: 誤解の訂正や見方の切り替えを担う否定はそのまま残す。例「遅いのはネットワークではなく、ディスクの書き込みだ」。これを「ネットワークに加えてディスクも遅い」と並べたり、「ネットワークよりディスクが遅い」と順位づけしたりしない。言い回しだけを整える。

形式の上限（目安）: 太字は 1,000 字あたり 2 箇所まで。箇条書きの行は全体の 15% 以下。思考の流れは地の文の段落で書く。ただし、箇条書きを地の文にすると同じ文末が 3 つ以上続くときは箇条書きのまま残し、15% の目安より優先する。並列なだけの項目も箇条書きのままでよい。絵文字は使わない。

問題: 否定は存在しない相手との対立を演出し、読者に余計な処理をさせる。英語ブログの "Not just X, it's Y" の直輸入で、2 回以上出ると型が露出する。太字ラベルは内容の言い換えで情報がゼロ。
判定: `slop_scan.py` の `negative_parallelism`・`excess_bold`・`excess_list`・`emoji_prohibited`（pathology "3"）。手で探すなら `ではない。.{0,40}だ。` が 2 回以上、`単なる.{0,20}ではな`、太字ラベル `^\s*[-*]\s*\*\*[^*]+:\*\*`。前置き・後置のラベリングは `meta_filler`（`phrases.md` 3・5）。
足さない: 否定を残すときに、元にない理由の文や強調語（「そのもの」）を足さない。箇条書きを地の文にするとき、元にない評価や義務（「〜が大切です」「〜する必要があります」）を足さない。

## 4. 三点セットの強制

問題: 本当に 3 つなら 3 つでよいが、無理に 3 つに丸める／4 つあるのに 3 つに削るのは型。「3 つにまとめると」で始まる文を疑う。
判定: `3つ(に|の)(まとめ|ポイント|理由)` ＋ 並列が均一すぎる箇条書き。

## 5. リズムを均す

| AI版 | 人間版 |
|---|---|
| 高速です。安全です。無料です。 | 高速で、安全。しかも無料。 |
| （全文が「〜です／〜でしょう／〜ます」で終わる） | ですます調に体言止めと短い断定を混ぜる |

問題: 文長・語尾・トーンにムラがなく、機械的な均一さが残る。完璧すぎる文章自体が AI 臭。
判定: 同一語尾（です/ます/でしょう）が 4 文以上連続。
注記: 体言止めを混ぜるのは 1〜2 文まで。3 文以上続けると 2 の `taigen_run` に当たる。リズムを整えるときも、11 で決めた立場の文末（勧め・決まり・説明）は変えない。AI 臭のない自然な文は、文末だけを理由に書き換えない。

## 6. 命題型見出し・区切り線で二要素詰め込み

問題: 見出しを断定命題にする（「X は Y である」型）、`---` 区切りで無関係な 2 要素を 1 ブロックに押し込む、300 字以下のセクションに小見出しを付ける、はいずれも構造の水増し。
判定: H2/H3 が述語を含む命題文／本文 300 字未満に小見出し。

## 7. 主語の過剰明示

| AI版 | 人間版 |
|---|---|
| このツールは高速です。このツールは安全です。 | 高速で、安全 |

問題: 毎文に同じ主語を置き直す。日本語は主語省略が自然なのに英語的に明示する。
判定: 同一主語が連続文の文頭に 3 回以上。
注記: 2 は「欠けた S/O を（前後に書いてあれば）戻す」話、本節は「同じ主語を毎文置き直す」話で、両立する。

## 8. 一文一行・パラグラフライティングの不在

問題: 1 段落が複数トピックを混ぜる／topic sentence が段落頭に来ない。推敲時は一文一行に展開して各文の役割を点検し、段落は「結論文→根拠」の順に組み直す。段落を分けるときは文の順序を崩さない。話題の違う段落どうしを 1 つにまとめない。
判定: 1 段落 6 文超かつ topic sentence が段落末にある。

## 9. 全角ダッシュ・中黒並列

| AI版 | 人間版 |
|---|---|
| 主要な経路——特に決済まわり——は二重に監視する | 決済まわりをはじめとする主要な経路は、二重に監視する |
| 再起動が要る——設定はキャッシュされるため | 設定はキャッシュされるため、再起動が要る |
| 速度・安定性・拡張性・運用性の向上 | 速度と安定性を上げ、拡張と運用もしやすくする |

ダッシュは英語の em dash の癖で、挿入なのか理由なのか言い換えなのかを読み手に推測させる。前後のかかる範囲を見て、助詞でつなぐか 2 文に分ける。ダッシュを外して 1 文につなぐと、前にある理由や条件（「〜ため」「〜なら」）が後ろまでかかってしまうなら 2 文にする。

中黒で名詞を 3 つ以上並べると、項目どうしが並列なのか対比なのか手段なのかが消える（2 の過圧縮と同じ根）。関係が読めないときは助詞と動詞で開く。外来語の区切り（ユーザー・インターフェース）や定着した複合語（研究・開発）は対象外。

問題: 記号が文の関係を運ばず、読み手が関係を推測する。
判定: `——|――|—|―`（全角ダッシュ・em dash）、`[^\s・]{2,}・[^\s・]{2,}・[^\s・]{2,}`（中黒 3 項以上）。

## 10. 予告だけの文

| AI版 | 人間版 |
|---|---|
| ここで押さえておきたい点がある。依存のバージョンは先に固定する。 | 依存のバージョンを先に固定しておくのが大事だ |
| 運用面で気をつけたいことがあります。夜間のバッチは手動で止めないでください。 | 運用面では、夜間のバッチを手動で止めないよう気をつけてください |

中身を言わずに予告だけする文は、予告の言葉が示していた重さ（押さえておきたい・気をつけたい）を述語へ移して、続く中身の文と 1 文にまとめる。1 文にまとめると意味が変わる場合はまとめずに残す。直後に表や箇条書きが来る導入文は対象外。

問題: 文字数を稼ぐだけで情報がなく、読み手は次の文まで中身を待たされる。
判定: `(点|こと|ポイント)が(ある|あります)。` で終わり、次の文が中身を述べている箇所。

## 11. 文末の立場の混在

日本語は主語を省くぶん、文末が「誰が動くのか」「決まりなのか、勧めなのか、説明なのか」を伝える。AI は文書の立場を決めずに 1 文ずつ文末を選ぶため、方針（〜します）・勧め（〜しましょう）・評価（〜ことが重要です）が混ざる。

| 立場 | 文書の例 | 文末 |
|---|---|---|
| 勧め | 心得、助言、呼びかけ | 〜しましょう／〜してください（動くのは読み手） |
| 決まり | 運用ルール、手順書、仕様 | 〜します（理由や前提を述べる文は「〜ことが重要です」のままでよい） |
| 説明 | 技術解説、報告、体験 | 〜です／〜した（書き手側の予定は「〜します」のまま） |

| AI版（運用ルールの文書） | 人間版 |
|---|---|
| 鍵は 90 日ごとに更新しましょう。更新記録を残すことが重要です。 | 鍵は 90 日ごとに更新します。更新記録を残すことが重要です。 |

手順: 依頼にある行き先と読み手から立場を 1 つ決める（分野の名前だけでは決めない）。決まらなければ本文の手がかり（主語、宛名、見出し）を見る。宛名や「当チームでは」のような手がかりがなく、読み手にしてほしい行動を並べている文書は勧めとして読む。

直すのは混在しているときだけ。そろっている文末は変えない。そろっていること自体が書き手の立場の手がかりになる。手順を「〜します」で書いて最後の 1 文だけ「〜しましょう」で結ぶ形と、原則を述べてから手順を並べる形は、混在とみなさない。同じ立場の中の強さ（「〜しましょう」と「〜してください」）は変えず、強さを上げない（勧めを「〜しなければならない」にしない）。言い切りの説明を可能表現（〜できる）に変えない。

問題: 読み手は、その文が自分への依頼なのか、決まった方針なのか、ただの説明なのかを判断できない。
判定: 機械判定はしない。同じ文書に主語のない「〜します。」と「〜しましょう。」「〜ことが重要です。」が並ぶ箇所を目視で確かめる。
足さない: 文末をそろえるために主語を足さない。立場を手がかりから決めきれなかったときは、もう一方の立場で書く場合の文末を「書き手に確かめたい点」に 1 行で示す。
